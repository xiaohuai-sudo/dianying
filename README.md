# 镜间

中英双语电影视觉语言与美学分析网站。当前六部电影、人物、主创信息与 200 张图片均为网站功能演示而创作的虚构内容，不对应真实影片或演员。内容层包含 6 个分析维度、36 个视觉词条、36 个词条详情页和 12 篇美学专题。

## 运行

需要 Node.js 20.9 或更高版本，推荐使用 pnpm。

```bash
pnpm install
pnpm dev
```

## GitHub Pages 发布

项目已配置 `.github/workflows/deploy-pages.yml`。推送到 `main` 后会自动进行静态导出并发布到 GitHub Pages。仓库名变化时无需手工修改路径，工作流会把仓库名作为站点前缀注入构建。

公开地址：`https://xiaohuai-sudo.github.io/dianying/`

访问 `http://localhost:3000`，默认进入中文站。中文与英文路径分别为 `/zh/...` 和 `/en/...`，顶部“中 / EN”可在保留当前页面和查询条件的情况下切换语言。正式检查：

```bash
pnpm typecheck
pnpm lint
pnpm build
pnpm start
```

## 内容结构

- `app/[lang]/[[...slug]]/`：中英文页面分发，包括首页、探索、电影、画面、专题、视觉词条、对比、灵感板和版权页面。
- `components/`：双语导航、卡片、筛选、画面标注、对比、收藏、色卡与版权组件。
- `lib/data.ts`：六部作品、既有画面、12 篇专题及筛选项。
- `lib/i18n.ts`：中英文界面、内容本地化、结构化读图、相似理由与画面标注数据。
- `lib/extended-frames.ts`：新增 30 个画面的完整视觉分析与版权数据。
- `lib/types.ts`：内容、版权、筛选和灵感板的公共类型。
- `source-assets/frames/`：不直接公开的原创高质量源图。
- `public/images/frames-optimized/`：供网站加载的 480/960/1280/1672px 响应式 WebP。
- `scripts/optimize-images.mjs`：从源图重新生成公开图片的优化脚本。
- `scripts/extract-frame-tones.mjs`：从 `public/images/frames-optimized/*-1672.webp` 提取曝光阶梯、主导色与画面统计，写入 `lib/frame-tones.generated.ts`。
- `docs/image-prompts.md`：首批 50 张原创演示图的制作与审核记录。
- `docs/cinematic-expansion.md`：新增 150 张摄影技法画面的制作规范与清单。

视觉语言索引位于 `/zh/visual-index` 与 `/en/visual-index`。每个词条拥有独立详情页，包含定义、视觉作用、常见误读、观看提示、筛选入口和 6–12 个相关画面；新增术语时同步维护 `lib/visual-index.ts` 与 `lib/i18n.ts`。

## 探索、标注与对比

- 探索页默认跨作品混排，每次渲染 30 张；搜索、排序、筛选与加载数量保存在 URL。
- 同一分类内采用任一匹配，不同分类间采用同时匹配。
- 排序支持精选混排、最新作品、暖色情感、光影技巧和人物互动。
- 每张画面详情提供构图、光线和人物关系标注层，标注数据采用相对坐标，不修改原图。
- 对比工具最多容纳 4 张画面，并通过 `?frames=id1,id2` 形成可分享链接。

新增内容时先扩展 `lib/data.ts`，再把高质量源图放入 `source-assets/frames/`，文件名须与数据中的图片文件名一致。运行 `pnpm images:optimize` 生成公开 WebP 后再进行构建。图片必须保持原始宽高比，填写可描述画面内容的替代文字，并在电影、画面和专题之间使用稳定 slug 关联。

## 图片性能

GitHub Pages 不提供 Next.js 动态图片优化服务，因此项目在构建前预先生成四档 WebP。`lib/image-loader.ts` 根据浏览器通过 `sizes` 请求的显示宽度选择最接近的文件：卡片不会再下载详情页尺寸的大图，详情页仍能获得清晰版本。源 PNG 不放在 `public` 中，避免被静态部署产物重复发布。

```bash
pnpm images:optimize
```

优化脚本只重新生成比源图旧或缺失的文件，可以安全重复运行。提交新图片时，需要同时提交源图和生成后的 WebP。

## 色卡与影调数据

画面详情页的色卡由三层组成：手写主色（`lib/data.ts` 中的 `palette`）、从图片实测的曝光阶梯与主导色（`lib/frame-tones.generated.ts`）以及画面统计。实测数据由脚本扫描优化后的 WebP 生成，曝光分段以中间灰 0.18 为基准、每档约两档光圈；新增或替换图片后必须重新运行并提交生成文件：

```bash
pnpm palette:tones
```

色块文字颜色按背景亮度自动切换，色块可点击复制十六进制色值；这段交互是 `components/Palette.tsx` 中的客户端组件，页面本身仍为静态导出。

## 内容工作台（本机运行，不进 Pages 产物）

199 帧内容靠人工对账容易失真，`scripts/studio/` 提供一套只读仓库文件的本地工作台：

```bash
pnpm studio:audit      # 彩排台：每帧从生成记录到构建产物七个环节的对账表
pnpm studio:palette    # 色卡质检（终端版）：按色卡与画面的吻合度排名，给出建议动作
pnpm studio            # 色卡质检台（网页版）：http://127.0.0.1:4321
```

网页版质检台对每帧并排显示「当前色卡 ↔ 实测主色」，用 CIE76 ΔE 标出画面里找不到对应像素的颜色，并给出三个决定：**采用实测**（换成画面里真实存在的颜色）、**补全**（保留手写色卡，只补它没覆盖的颜色）、**标记刻意偏离**（确认手写色卡是叙事意图，不修改）。决定存在 `.studio/state.json`（已 gitignore），点「生成回填文件」写入 `lib/palette-overrides.ts`——构建时覆盖 `lib/data.ts` 的手写色卡，`data.ts` 本身不被修改，撤销只需在工作台里点「撤销」后重新回填。

工作台不进 `out/`：它不从 Next 路由渲染，只在本地起一个 Node 进程；线上产物里没有这个界面。

### 导演 / 摄影风格库（第一批 10 位）

```bash
pnpm studio:style                                                   # 交叉验证：每位档案的代表画面必须匹配到自己
pnpm studio:style-demo -- --frame teahouse-closing --tags 对称,低调光   # 端到端：匹配 → 差距 → 图片/视频两套提示词
```

- `lib/frame-features.ts`：浏览器与 Node 通用的画面特征提取（曝光阶梯、主导色、影调统计），口径与 `scripts/extract-frame-tones.mjs` 一致。
- `lib/style-profiles.ts`：10 位导演/摄影指导的档案。**只用能被像素证明的东西做指纹**（暗部/亮部占比、明度跨度、饱和度、色温倾向），构图与光位属于形式标签，由用户勾选，不假装能从色影调反推。
- `lib/style-match.ts`：匹配 + 逐维度的「差在哪、差多少、往哪改」+ 结构化提示词（图片与图生视频两套，视频另附运动描述）。
- 风格档案不使用任何真实影片剧照，示例一律指向站内原创画面；文案为公开资料整理，不冒充本人言论。

标定规则：任何一次指纹修改都必须让 `pnpm studio:style` 保持「自洽失败 0 位」。验证脚本会同时报告哪些档案在色影调上根本分不开（当前 7 组），这些只能靠构图/光位/运动标签二次区分——匹配结果里会显式提示，不会硬给一个「最像」。

## 收藏

灵感板保存在浏览器 `localStorage` 的 `jingjian:boards:v1` 键中，结构为 `{ version, boards, activeBoardId }`。只保存画面 ID，不保存或复制图片；切换语言不会迁移或清空灵感板。清理浏览器数据会删除收藏。

## 图片版权要求

每张公开图片必须保存：图片标题、作者、权利人、来源链接、来源类型、授权类型、版权状态、使用范围、是否允许下载、授权证明编号或备注、添加日期与审核状态。

版权状态只能为：

- 本站原创
- 已获授权
- 公有领域
- 开放许可
- 待版权审核

只有“审核通过”且不是“待版权审核”的图片可以出现在 `publicFrames`。不得录入“来源不明”“网络素材”“侵删”等状态；未经明确授权不得使用真实电影截图、海报、演员照片或受保护标志。开放许可内容必须记录具体许可名称和可访问的许可链接。

当前图片标记为“镜间原创演示资产”，仅用于本站功能演示和美学分析，不提供原图下载，也不构成商业素材授权。替换图片时必须同步更新版权记录并保留授权证明。

## 版权邮箱与上线检查

默认邮箱 `rights@jingjian.example` 是不可收件的演示地址。正式上线前设置：

```bash
NEXT_PUBLIC_RIGHTS_EMAIL=rights@your-real-domain.com
```

上线前还必须：

- 验证版权邮箱真实可收件。
- 将权利人表单接入安全的邮件或工单后端，并提供隐私说明和文件上传保护。
- 复核所有图片授权状态、来源链接与许可范围。
- 确认待审核内容不会进入生产数据。
- 检查页面不存在图片下载入口或商业使用暗示。
