## 一、先说结论

镜间的画面是「电影感影调」优先，因此视频生成要的是**低速度、高保真、可精确控镜**，
而不是「一秒出片」。可选两条路，建议都留：

| 用途 | 走哪条路 | 代表 | 单价 | 5 秒成本 |
|---|---|---|---|---|
| 高质量成片（对标可灵 3.0 / 即梦） | 标准模型 API（第三方模型直调） | `seedance2.0/图生视频`（即梦同源） | ¥0.6/秒 | ≈ ¥3.0 |

| 想改 ComfyUI 图、自己调参 | 自部署工作流（RH币按 GPU 秒计费） | MiniMax H3 FL2VA 开源版 / Wan2.2 / LTX2.3 | 0.2 币/秒（24G） | ≈ 36 币/3 分钟 |

一句话：**要「对标可灵和即梦」的效果，就用标准模型 API 里的 Kling 与 Seedance 两个系列**——
RunningHub 已经把这两家的官方模型接进来了，不需要自己搭工作流。

**记账口径（2026-09-23 起）**：本站对外统一用**积分**，不接支付。积分只是额度单位，
背后对应两种货源：自部署工作流的 **RH币**（按 GPU 秒）与第三方模型的 **￥**（按秒）。
因为第三方模型要求「企业共享 Key」，**默认路线走 RH币 的工作流**，积分与 RH币 同尺度换算；
成片档再按需开启第三方模型（见第七节）。

## 五、接进镜间（静态站）的方式

站点是 GitHub Pages 静态导出，**没有任何后端**，所以：

1. API Key 不能进前端。要么用 Cloudflare Workers / 阿里云函数 做一层薄代理（只做
   「收请求 → 调 RunningHub → 轮询 → 回 URL」，Key 只存在于函数环境变量），要么第一版
   干脆由你在本机跑，生成结果手动入库。
2. 接口是异步任务模型：`提交任务 → taskId → 轮询状态 → 取输出`。
3. 两类 Key 不能混用（官方文档明确）：
   - **会员消费 Key**：AI 应用 / ComfyUI 工作流 / 上传文件（`/task/openapi/ai-app/run`、`/task/openapi/create`）。
   - **企业共享 Key（Enterprise-Shared）**：标准模型 API（`/openapi/v2/...`）与 `/openapi/v2/media/upload/binary`。
     官方文档写的是：Model API 与 LLM API **仅支持企业共享 Key**。走 Kling/Seedance 直调就必须先有这个 Key。
4. 标准模型调用形如 `POST https://www.runninghub.cn/openapi/v2/<模型路径>`，body 里带 `apiKey`
   （不是 header），并**必须带 `Host: www.runninghub.cn`**，否则部分接口 403。任务类型建议 `ASYNC`。
   图片先传 `/openapi/v2/media/upload/binary` 拿 `download_url` 再作为入参。
   AI 应用/工作流则是 `POST /task/openapi/ai-app/run`（`webappId` + `nodeInfoList`）。
5. 工作流节点的图生视频入参：`firstImageUrl` / `lastImageUrl` / `duration` / `cfgScale` / `sound` /
   `multiPrompt`，可灵 3.0 还支持 `elementList`（最多 3 项）与 `multiShot` + `shotType` 自定义分镜。
6. 价格预估接口 `/openapi/v2/price-preview/...` 可以在用户点「生成」之前先报价（内部成本核算用）。

## 七、积分制（对外唯一的额度单位，不接支付）

### 单位与换算

- **1 积分 = 1 秒 Standard（24G）GPU 时间 = 0.2 RH币**。这样自部署工作流的成本天然就是
  积分，不需要二次换算：一条 5 秒 720p 的图生视频在 Standard 上跑 60–180 秒 → **60–180 积分**。
- 第三方模型（走 ￥）按内部成本汇率折算，汇率是**参数不是常量**（¥0.05/积分起步，
  随 RH币 充值折扣与厂商调价改），写在配置里，不硬编码到前端。
  参考：seedance2.0 一条 5 秒 ≈ ¥3.0 → 约 60 积分；可灵 3.0-std ≈ ¥2.6 → 约 52 积分。

### 规则（第一版）

| 动作 | 消耗积分 | 说明 |
|---|---|---|
| 影调诊断 / 风格匹配 / 提示词生成 | **0** | 全在浏览器本地算，没有服务端成本 |
| 试镜档：自部署工作流 5 秒 720p | 60–180 | 按实际 GPU 秒结算，预扣 180、多退少不补 |
| 成片档：第三方模型 5 秒 | 52–60 | 需先有企业共享 Key 才会开启 |

- 新用户注册赠送 **300 积分**（够一条 5 秒成片，或两条试镜），每日签到 +20。
- **预扣 → 结算 → 退还**：提交任务时预扣上限值，任务成功后按实际秒数结算，失败/超时**全额退还**。
  幂等键用 RunningHub 的 `taskId`，重试不重复扣。
- 流水表只追加、不修改（`credits_ledger`：user_id / delta / reason / task_id / created_at），
  余额由流水汇总得出，不做「余额字段自增」。
- **不接任何支付**：积分只来自赠送、签到、邀请码。将来若要卖，是加一条充值入口，不动上面这套。

### 静态站的现实

GitHub Pages 上没有服务端，纯前端的额度存在 `localStorage`，清缓存即归零——**只能当体验用，
不能当准数**。要真做准，需要一个薄代理（Cloudflare Workers + KV/D1，只做「发任务 / 查任务 /
扣积分」三件事，Key 只存在环境变量里）。第一版建议：前端展示额度 + 服务端按 IP 限流，
把「严格账本」放到代理上线之后。

## 八、积分路线的最终选型（2026-09-23）

模型不是猜的：走 `POST /api/portal/workflow/detail`（body `{"workflowId": …}`）拿到了每条工作流
真实加载的权重清单 `usedModels`，据此判定是否自部署、跑不跑得动 24G。

### 主力：Wan 2.2 I2V-A14B（fp8）+ LightX2V 蒸馏 LoRA

镜像站上跑的确实是同一套权重：

```
Wan2_2-I2V-A14B-HIGH_fp8_e4m3fn_scaled_KJ.safetensors
Wan2_2-I2V-A14B-LOW_fp8_e4m3fn_scaled_KJ.safetensors
Wan21_I2V_14B_lightx2v_cfg_step_distill_lora_rank64.safetensors
umt5-xxl-enc-bf16.safetensors / Wan2_1_VAE_bf16.safetensors
```

选它的三条理由：**fp8 能在 24G（Standard）跑**，积分不用翻倍；**LightX2V 蒸馏把采样压到 6 步**，
时间就是积分；社区共识是 WAN 的**运镜与电影感强于 LTX**（「理解重量感与调度」），正好是镜间
要的「导演视角」。缺点是节点多、默认分辨率 720p 档。

### 两个工程细节

- **注入参数用 AI 应用接口**：上表有 `webappId` 的可以直接
  `POST /task/openapi/ai-app/run`，`nodeInfoList` 里填 `{nodeId, fieldName, fieldValue}`；
  LTX 那两条没发 AI 应用，只能走 `POST /task/openapi/create`（传 `workflowId`）。
  图片类字段的值必须是先上传拿到的 `fileName`，不能填 URL。
- **镜像站上没有官方工作流**：2846 条视频工作流里 `systemWorkflow` 全为 false，全是社区作者。
  所以「选工作流 = 选作者」：Aiwood爱屋研究室（46 条 / 累计 21.8 万次，LTX 系）、
  T8star-Aix（113 条 / 11.1 万次，Wan 加速系）、Little Wrangler（29 条 / 6.6 万次，渠道版）、
  破狼（53 条 / 6.2 万次）更新最勤。
